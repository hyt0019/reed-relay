# 使用手册

## 听谱：从音频到可校对曲谱

1. 选择音频或拖入文件，可一次选择多首。主旋律优先生成单声部草稿；完整候选保留所有识别音符。
2. 点击开始转谱。后台依次处理每个文件，可以取消；某首解码失败不会使其余文件停止。完成的每首工程保存在数据目录的 `conversions` 中，主界面显示最近成功的结果。
3. 在钢琴卷帘或列表点击音符。橙色代表较低的模型分数，该分数不是经过校准的正确概率。时间轴可缩放为 12 / 24 / 48 秒视窗，并拖动下方滑块定位。
4. 试听原音可比较选中音符附近的片段；勾选循环可反复播放。取消选中后试听全曲。点击口琴试听进入共享试听页，用口琴音色比较音高与时值。
5. 修改起始毫秒、时长和 MIDI 音高；支持新增、删除、等分、合并下一同音高音符、撤销与重做。修改后自动保存，最多保留当前会话 50 步撤销。
6. 页面下方的当前场景检查可点击定位音域外、重叠和音分偏移等问题。是否可演奏取决于当前场景映射；它不是转写准确率评估。
7. 保存 JSON 工程可带走原始候选和修改结果；MIDI / 文本简谱导出当前编辑结果。若源音频搬家，点击关联原音重新选取，再保存工程。

主旋律转换会考虑候选的持续时间和换音成本，并使用当前修整参数，避免在每个候选交接点频繁跳音。完整候选模式不做碎音过滤；两种模式均保留完整候选备份。

## 减少碎音与撕裂感

在听谱或试听页使用「连贯修整」。已有工程无需重新转谱。

1. 初次使用保持碎音阈值 **80 ms**、衔接间隙 **50 ms**，点击「连贯修整」。低于阈值的音符会删除，小间隙通过延续前音衔接，后一个音的起始时间不变。
2. 再试听比较；若快速装饰音被删掉，点击「撤销」，降低阈值或设为 0 后重试。80 ms 是可调策略，不能作为所有歌曲的最短合法音符时值。
3. 「合并相邻同音」默认关闭，保留有意的重复起音。听到同一个音被错误切成几段时可开启；音分不同的片段不会合并。
4. 大于衔接阈值的休止保留，不移动后续节拍、不移调、不改变整曲总时长。多声部修整会先提取单声部草稿，完整候选仍保留。
5. 「重提主旋律」从完整候选重新生成草稿，适用于旧版频繁跳音的结果；它会替换当前编辑结果，可撤销。修整仅处理当前编辑谱，原始候选不覆盖。
6. 满意后点击「导出曲谱」保存 JSON，再在风箱中打开该文件。修整结果也会进入自动保存；撤销恢复修改前的音符。

阈值会保存，下一次主旋律转谱沿用这些参数。若本来的休止较短，间隙衔接可能改变该处的断奏，可调小或设为 0。自动修整改善连续性，仍需听原音确认旋律选择。

原始候选始终单独保留；恢复原始候选会替换当前编辑列表，可撤销。主旋律提取只做单声部简化，不进行人声分离。声部筛选主要用于多通道 MIDI；音频转写不会自动识别每种乐器的身份。

文本简谱使用固定 `1=C4`、升降八度标记和绝对秒数，不改变原始音高。首版不估计 BPM、拍号或调式；工程 `bpm=120` 是参考占位，绝对事件时间不受它影响。微分音/滑音保存在 JSON 附加数据中，常规 MIDI 导出当前离散音符，不导出弯音曲线。

## 口琴试听：两个模块均可独立使用

打开左侧「试听」，载入曲谱或 MIDI，也可使用当前已打开的曲谱。

- 点击「播放 / 继续」生成口琴音频并播放；播放中再次点击暂停。生成过程中该按钮用于取消，取消后旧任务不会重新开播。
- 拖动进度条定位；调整音量立即生效。速度支持 25%–200%，通过重排音符时间实现，保持音高。改变速度或音色模式会停止当前试听，再次播放时重新生成。
- 点击时间轴中的音符，然后点击「循环选中音符」；也可填写起点和终点秒数，勾选「循环片段」。点击「恢复全曲」清除选段。
- 「旋律校对」按曲谱的原始音高、音分和时值，使用稳定口琴音色，支持多声部候选试听。
- 「游戏效果」应用当前演奏移调、单声部选择、映射和长音选项；有无法演奏的音域或重叠问题时先处理问题列表。已录音区的微小音准与起音变化会被模拟。
- 试听不会发送游戏按键。启动游戏演奏会停止试听；改绑按键、换曲或关闭程序也会停止相应播放。

音色来自五种录音状态的泛音、包络和音高轨迹：普通 C4/D4、低音、半音和高音。正常1第三次不参与建模，其他未录音符从邻近音区推算。原录音没有装进程序，随包提供的是小型合成参数。游戏效果是模拟，超出录音长度的发声保持最后的模型状态，不能等同于每个音都已在游戏中验证。代码仓库提供参数提取脚本 `packaging/analyze_harmonica.py`。

## 按键与口琴预设

打开「按键」，点击八个音符键、鼠标修饰或控制热键中的任意一项。

1. 出现「绑定」弹层后，按下新键；绑定鼠标时，在弹层的提示区域点击左、中、右键。
2. 控制热键支持 Ctrl/Alt/Shift/Win 与主键组合；音符/修饰按单键绑定。F12 为系统保留热键，不接受绑定。
3. 成功后立即保存并提示结果。启动绑定的那次点击不会被当成左键；弹层只在绑定期间捕获输入。
4. 冲突、全局热键注册失败或保存失败时保留原配置并显示原因，可直接换键重试。Esc、取消按钮、失焦或超时退出绑定。绑定期间暂停本程序的演奏热键。

默认普通音为 C4、D4、E4、F4、G4、A4、B4、C5，对应 Z/X/C/V/B/N/M/逗号。鼠标左、中、右分别为降八度、升半音、升八度；按住生效，松开恢复。该内置预设依据实录和音阶推算，可以直接进入演奏，无需再走调音向导。

「使用内置音高」恢复内置音高与修饰关系，保留已经绑定的键盘、鼠标和控制热键。「高级音高映射」可设置其他乐器的实际 MIDI 音高、修饰音程、参考 A4 频率及组合，然后点击「保存映射」。两个复合修饰按音阶推断；若游戏不支持，可分别关闭。场景可以导入/导出。

旧的未校准默认模板会迁移为内置预设；自定义音高、按键和已保存的校准值保留。配置中的 `calibrated` 仅用于兼容旧版本，不再作为开始演奏的门槛；`pitch_source` 区分采样推断、自定义与旧实测配置。高级映射改变的是曲谱到按键的对应关系，无法直接改变游戏音源本身的调律。

## 风箱：预演与游戏演奏

1. 添加 JSON 或 MIDI 曲谱；也可直接载入原创练习曲。播放列表可用上下箭头排序。
2. 默认预演不发送系统输入。检查键位高亮、曲目进度与演奏检查列表。
3. 音域外音和重叠音默认阻止演奏。可手工校对，或显式选择提取主旋律、跳过音域外音。演奏移调默认为 0，所有演奏选项都不会修改原谱。
4. 刷新并选择游戏窗口，关闭预演。热键成功注册、曲谱检查通过后可以开始。
5. 进入游戏演奏界面，按 F8。默认有 3 秒准备时间；F6/F7 切歌，F10 紧急停止。切歌默认停止，勾选“演奏中切歌后自动继续”才从新曲开头重新开始。

鼠标修饰先按下，音符随后按下；换音和停止会按顺序释放。游戏窗口失焦立即停止，需再次启动。实际输入使用 Windows SendInput；游戏可能受权限级别、输入处理方式或自身限制影响，不保证所有游戏都接受。

**单音与长音**：用户确认游戏口琴按下即刻发声，连续切换音符不会累积气息问题。因此不添加统一起音提前量，也不安排全曲换气。仅单个音实际持续超过约三秒时提示可能不稳。

- 「保留长按」为默认，保持该音的原时值，游戏可能出现原生气息抖动。
- 「分段重奏」将过长单音分成实际不超过 2.6 秒的小段，会再次触发起音，原谱不被改写。
- 「同音松键间隔」可设 0–150 ms；默认35 ms是可调整的演奏策略，不是实录测出的最小响应值。只在同音紧邻重按时提前结束前音，下一音仍按原来的节拍开始。不同音连续切换不加此间隔；设0保持原始交接。
- 速度变化后按实际持续时间判断长音。例如四秒的谱面长音以200%速度演奏，实际两秒，不分段。

速度、准备时间、移调与简化选项会保存。每次启动仍默认预演，目标游戏窗口需重新选择，避免重启后把按键发送给错误窗口。

## 数据与排障

打开左侧「存储」，点击「选择目录」。新目录用于转谱工程、自动保存、场景/播放列表/偏好和临时口琴 WAV；手动导出默认从这里开始，每次也可另选文件位置。

默认数据目录为程序旁的 `local-data`，本项目位于 D 盘，因此默认文件也保存在 D 盘。若程序放在 C 盘且还没有位置记录，首次交互启动先要求选择目录，取消则退出。目录记在程序旁的 `storage-location.json`，重新启动会继续使用。程序目录需要可写，以保存这份位置记录；不会写入失败后静默退回 C 盘。

源码启动的程序根目录是仓库；便携包的程序根目录是 `ReedRelay-Player` / `ReedRelay-Converter` 文件夹的共同上级。本地 `dist` 构建使用仓库的位置记录。两个模块可以单独放置和运行；分别放在不同根目录时各自记录位置，可选择同一个数据目录。

更换目录会复制已有工程和配置，并重写目录内工程的播放列表/音源路径，原目录保留；试听缓存重新生成。同名文件内容不同会拒绝切换，请选空目录。写入或位置记录失败时仍使用原目录。另一个已打开的模块需关闭后重新启动，才能读取新位置。

第一次升级会尝试从旧 `%APPDATA%\ReedRelay` 复制数据，不删除原文件。遇到冲突时会提示；可在存储页打开旧目录，重新打开原工程并导出到选定位置。`REED_RELAY_DATA_DIR` 环境变量仍可固定启动目录，使用它时界面目录选择不可用；移除该启动配置后可正常选择。

| 文件/目录 | 用途 |
|---|---|
| `profile.json` | 当前已保存场景 |
| `profile.before-calibration.json` | 旧版本留下的场景备份，可通过「导入场景」恢复 |
| `playlist.json` | 曲谱文件路径列表 |
| `preferences.json` | 演奏选项 |
| `conversions/` | 每首成功转换的完整工程 |
| `autosave.reedscore.json` | 最近编辑的恢复工程 |
| `harmonica_*.wav` | 临时口琴试听音频，正常关闭时清理本次会话创建的文件 |
| `startup-player.log` / `startup-converter.log` | 便携程序启动失败时的诊断 |

`preferences.json` 也保存碎音阈值、间隙衔接和同音合并选项。启动失败日志优先写入启动配置目录或程序旁的数据目录。

- 热键注册失败：查看底栏信息，改用未被其他程序占用的组合。Windows 保留 F12，不能使用。真实演奏会等待热键就绪。
- 音高不对：先用旋律校对试听检查源谱，再检查当前乐器预设；不同游戏/乐器可编辑高级映射或导入对应场景。
- 试听无声：检查试听页音量、Windows音量混合器和当前默认输出设备。试听使用系统默认音频输出，界面不再要求录音设备或调音。
- 原音找不到：关联原音，再保存工程。曲谱文件不会嵌入原音频。
- 转谱依赖缺失：重新运行 `setup.ps1 -Module all`。ONNX 安装中缺少 TensorFlow/CoreML/TFLite 的提示不代表 ONNX 不可用。
- 找不到 Python：指定 `-PythonPath`；不要使用尚未在本项目支持范围内的 Python 3.14。
- 窗口内容未全部显示：界面可滚动，编辑/导出与保存场景按钮位于页面下方。
- EXE 无法启动：保留 EXE 旁完整 `_internal` 文件夹，检查启动日志。当前构建在本机 Windows / Python 3.12 环境验证，尚未完成所有 Windows 版本的兼容性矩阵测试。

## 命令行

```powershell
# 不启动 GUI 进行转谱（默认主旋律草稿）
.\.venv\Scripts\python.exe -m reed_relay.converter.transcribe 'input.mp3' 'output.reedscore.json'
# 保留全部候选
.\.venv\Scripts\python.exe -m reed_relay.converter.transcribe 'input.mp3' 'output.reedscore.json' --all-notes
# 便携听谱也可转换，出错时保存 output.reedscore.json.error.txt
.\dist\ReedRelay-Converter\ReedRelay-Converter.exe --transcribe 'input.mp3' --output 'output.reedscore.json'

# 两个独立包均能生成口琴试听 WAV
.\dist\ReedRelay-Player\ReedRelay-Player.exe --render-audition '曲谱.reedscore.json' --output '口琴试听.wav' --audition-speed 1.25
# --audition-mode game 使用游戏音色模型；命令行渲染不应用 GUI 中的移调/长音配置

# 两个独立包均可修整已有曲谱；另存保留原工程
.\dist\ReedRelay-Player\ReedRelay-Player.exe --repair-score '曲谱.reedscore.json' --output '修整.reedscore.json' --short-note-ms 80 --gap-ms 50
# --short-note-ms 0 保留快速音符；--merge-repeats 开启同音合并

# 可选硬件自检：播放 1.5 秒低音量 A4，采集默认输出并保存数值诊断（不保存录音）
.\dist\ReedRelay-Player\ReedRelay-Player.exe --check-loopback --output 'loopback-check.json'
```
