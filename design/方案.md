## 2026-10-02 当前实施方案：内置口琴、试听与点击绑定

本节替代下文旧版“先调音再演奏”的流程。用户已授权开工并要求每阶段验证、提交、推送。

- 用户确认：音符按下即刻发声；连续切换音符不会累积气息问题；仅单个音持续过长（约三秒后）会不稳。不添加统一起音提前量，不插入全曲换气间隔。
- 使用已有七份本地录音，新增的“连按1”（6.57 秒）、“连续切换12”（8.77 秒）用于检查重复音/切音表现。排除“正常1”第三次演奏，不再要求用户逐音补录。音频没有同步按键时间，不能据此伪造精确输入延迟。
- 内置 C4–C5 基础映射与 -12/+1/+12 修饰。C4、D4 和三种修饰取自现有录音，其他音和组合按音阶推断；用来源字段区分“预设推断”和“人工校准”，不把预设标记为已实测所有音。
- 用干净录音提取泛音、起音和长音包络，生成小型参数音色库；普通、高低音区和半音采用对应录音模型，其他音就近推算。原录音、原曲和派生曲谱继续仅保留本地。公开仓库仅保存合成参数和可复现的分析工具。
- 删除调音页、测音仪和游戏内调音向导入口，以“曲谱试听”和“按键设置”替代。保留场景导入/导出、自定义映射及旧配置兼容；旧的未校准默认模板自动迁移到内置预设，自定义映射不被覆盖。
- 听谱、风箱都可独立进行口琴曲谱试听，支持暂停/继续、进度定位、片段循环、音量和保持音高的速度调整。“旋律校对”用稳定音准，“游戏效果”模拟已测起音、音准和长音变化；推算结果不等于真实游戏已经验证。
- 点击绑定后进入捕获状态，支持键盘、演奏用鼠标键和键盘组合热键；启动点击不计入绑定。捕获期间停止演奏并暂停自己的全局热键；取消、失焦、超时恢复原绑定。冲突和注册失败不覆盖旧配置。
- 同音紧邻重按保留释放/按下边沿；连续换音按原谱时间交接，不安排换气。超过阈值的单音提示可能不稳；默认保持原时值，提供明确可选的分段重奏，用户知道重奏会重新起音。速度变化后以实际持续时间判断长音。
- 由于用户已提供连按和切换资料，本轮取消强制一键采样前置步骤。实际游戏验收由用户现场演奏确认；本机用输入接收器和现有录音完成可验证部分，不自动向运行中的游戏发送测试按键。

## 1. 目标与边界

做两个可独立启动的 Windows 桌面程序：**听谱**负责把音频转成可校对、可导出的曲谱；**风箱**负责读取曲谱并在游戏前台按时间发送口琴按键。二者共享一种公开、可读的曲谱文件格式，但风箱不需要安装或运行听谱，听谱也不需要连接游戏。

目标是保留源音高和节奏，**默认不移调、不偷偷改八度、不丢弃无法演奏的音**。任意混音 MP3 无法保证完全准确的自动扒谱，单音口琴也无法同时复现所有和弦。因此软件输出两层结果：

1. **原始转写谱**：保留识别到的各声部音符、绝对音高、起止时间、力度与置信度；允许人工改错。
2. **游戏演奏方案**：依据当前键位和游戏音域，把可演奏音符映射为键盘与鼠标事件；冲突音、音域外音和不确定音显式标记，并让用户选择主旋律、保留某声部或手工处理。任何简化都只作用于演奏方案，原始转写谱不被覆盖。

## 3. 曲谱转换器「听谱」

### 输入和工作流

- 拖入或选择 MP3、WAV、FLAC、OGG、M4A；批量导入后逐首处理。先解码为统一的内部 PCM 音频，解码失败时给出文件与原因。
- 模式：**主旋律优先**（默认）、**完整音符候选**。支持导入 MIDI 后筛选其通道声部。混音的源分离属于后续扩展，首版主旋律是保留原始候选的单声部简化。
- 推断音符的音高、起点和终点；显示波形概览与原音高钢琴卷帘。时间轴以毫秒级绝对时间保存，不量化节奏；首版不估计 BPM、拍号或调式。
- 给低置信度、密集重叠音、疑似颤音/滑音、超游戏音域的片段上色。可循环试听、点击片段听原音、调整音高和时长、拆分/合并音符、撤销/重做，再重新评估可演奏性。
- 输出 `.reedscore.json` 作为两个模块的交换格式；另导出 MIDI 和可阅读的简谱。若用户需要五线谱打印，再增加 MusicXML/PDF 导出，不把它作为首版准确性的前提。

### 技术路线

- Windows 桌面界面：**PySide6 + Qt Quick/QML**，两个独立入口和可共用的设计组件。Qt 官方提供 Python 绑定与 Qt Quick 控件。[Qt for Python](https://doc.qt.io/qtforpython-6/)
- 基础转写候选：**Basic Pitch**。它支持常见音频格式、返回 MIDI 与音符事件，官方也说明其效果以单个乐器的录音为佳。因此混音不能只依赖一次模型输出。[Basic Pitch 官方仓库](https://github.com/spotify/basic-pitch)
- 后续可选声部分离：**Demucs** 可分出人声、鼓、贝斯和其他声部；复杂伴奏中的旋律仍需人工校对，首版暂未接入。[Demucs 官方仓库](https://github.com/facebookresearch/demucs)
- 音频解码使用 SoundFile，不能解码时调用 ImageIO-FFmpeg 随包的 FFmpeg。转写模型与解码器只属于听谱，风箱独立包排除这些依赖。组件说明见 `docs/THIRD_PARTY.md`。

## 4. 自动演奏器「风箱」

- 独立打开 `.reedscore.json` 和播放列表；也可手工导入符合格式的第三方曲谱，不需要先启动听谱。
- 用户设置**启动/停止**、**上一首**、**下一首**三个全局热键；界面显示当前绑定，保存时检查重复绑定并尝试系统注册。默认 `F8 / F6 / F7`，紧急停止为 `F10`。系统保留的 `F12` 不接受注册。
- 提供单独的**紧急停止**热键。停止、切歌、游戏失焦、异常退出时立即释放所有由程序按下的键盘与鼠标按钮。切歌时停止旧曲，更新列表选中项；可配置是否自动从新歌开头继续。
- 使用高精度时钟按曲谱起止时间调度按下与松开事件。先按修饰键、再按音符键；换音时按游戏实测结果处理短间隔和键释放。速度倍率和启播延迟可调，原谱时间不随之改写。
- 用户选择目标游戏窗口，只有该窗口位于前台时才发送演奏按键；运行状态、当前音、歌曲进度与无法演奏片段清楚可见。提供不向游戏发送输入的预演模式，用来检查排程和键位。
- Windows 输入采用系统 `SendInput`；其权限级别有限制，某些游戏可能拒绝模拟输入，需要以游戏实测确认。[Microsoft SendInput 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)

```text
  docs/                 # 用户手册、键位校准、格式说明、截图
```

交换文件采用带版本号的 UTF-8 JSON；每个音符至少包含 `start_ms`、`duration_ms`、`midi_pitch`、`voice`、`confidence`，曲目包含源文件信息、绝对时间基准及 `original_notes` 原始候选。`confidence` 为模型激活值，不是准确概率。微分音或滑音保留附加音高偏移数据；游戏只支持离散音高时标记不可精确复现。场景配置与原谱分别存储，按需生成按键排程。对非法时间、负时长、未知格式版本明确报错。

## 6. 两个界面的关键交互

**听谱**：导入 → 选择识别模式 → 查看处理进度 → 波形与音符对齐校对 → 查看“低置信度/音域外/重叠音”列表 → 试听 → 导出。界面保持可取消、可撤销、可恢复工程；长时间运算在后台执行，不冻结窗口。

**风箱**：添加曲谱 → 选择游戏键位配置 → 测试按键映射 → 设置热键与目标窗口 → 在游戏中一键启动/停止、切歌。大字号状态、当前音高和醒目的紧急停止提示保证边游戏边看也能辨识。键位冲突、音域外音以及游戏失焦都给出明确原因和下一步操作。

三个初期视觉方向保留在同目录预览图中，用户已选择 A「谱台」。实际界面截图见 `docs/screenshots`，所有功能与操作以实际程序和使用手册为准。

## 7. 实施顺序与验收

1. **确认游戏映射与原型**：记录 8 个基础音实际音高、三个鼠标修饰的音程、是否可叠加、长按时值和连音行为；根据选中的预览方向定稿两套界面。
2. **定义共享曲谱格式**：先做模式校验和样例文件，使转换器、演奏器可以分别开发和单独运行。
3. **完成听谱最小闭环**：导入音频、生成原调事件、时间轴校对、试听、导出。使用已知音高/时值的测试音频校验，不以“看起来像曲谱”作为准确性依据。
4. **完成风箱最小闭环**：导入手工样例曲谱、热键和键位配置、预演、游戏窗口前台守卫、启动停止切歌、释放所有按键。重点测试快速连续音、长音、切歌中止和失焦。
5. **整合与交付**：完成本地样例真实音乐转写、已知音高时间测试、界面检查、Windows 独立构建与运行检查，形成 README、安装/配置文档与实际截图。听谱与风箱分别打包，风箱不携带音频模型。真实游戏和麦克风硬件留待现场确认；公共二进制 GitHub Release 与录屏不计入本轮交付。

验收关注三件事：**音高和事件时间是否与已知样本一致；谱中无法演奏的部分是否被完整标出；任何停止路径是否都能释放按键**。真实流行歌曲的转写结果由用户在校对界面确认，不能承诺对任意 MP3 全自动零误差。

## 8. 仓库命名与介绍

- 推荐仓库名：`reed-relay`。Reed 指口琴簧片，Relay 指从声音到谱、再到游戏输入的传递；英文短、便于输入，项目可用中文名「风箱 / 听谱」。
- GitHub 简介（中文）：`将音频转成保留原调的可编辑曲谱，并通过可自定义键位在游戏中自动演奏的双模块桌面工具。`
- GitHub description（英文，可二选一）：`Audio-to-score transcription and configurable in-game harmonica playback for Windows.`
- README 首页应展示两模块关系、支持格式、三步上手、键位校准、安全停止、准确性边界、两套程序独立启动方式、截图、许可与模型来源。

## 9. 现场确认资料

视觉与仓库已经确定。现场确认仍需要游戏名称与版本、8 个基础音和三个鼠标修饰的实录音或键位说明，以及游戏是否接受普通 Windows 模拟输入。软件与预演功能可以独立使用；用户通过已实现的调音页完成实际映射后进行游戏演奏验证。
